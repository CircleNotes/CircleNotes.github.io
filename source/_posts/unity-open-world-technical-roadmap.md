大世界技术涉及资源、表现、模拟和内容生产等多个系统。只把地图切成多个场景，或单独优化一次 Draw Call，都还不足以回答它们如何协作、何时加载与释放、以及如何在不同设备上保持稳定。

这份路线从成熟作品提出的问题出发，在 Unity 中建立小规模实验，再把验证过的部分整合成可巡游的世界样例。研究沿着“案例 → 假设 → 对照实验 → 双平台测量 → 选型复盘”推进，每项任务都保留前置依赖、行动步骤、产物与验收条件。

**阅读方式：** 先看阶段总览与里程碑，再按当前问题进入详细任务。案例资料是研究入口，任务不是已完成清单；官方确认、观察与推测会分开记录。

## 目标与范围

以当前 Unity 项目为实验载体，建立“成熟案例研究 → 方案比较 → 小规模实验 → 双平台测量 → 综合样例 → 复盘”的学习路径。最终交付可复测的 Unity 大世界技术 Demo、技术决策记录与可复用的模块边界，而不是复刻某款完整游戏。

技术栈以 Unity 为主，目标平台同时覆盖 PC 与移动端。案例从《艾尔登法环》扩展到不同世界结构与内容约束的作品，通过对比方案寻找适用边界。具体测试设备、Android/iOS 覆盖范围、性能预算与时间安排在任务 00.01 中确定，先建立依赖关系，再制定日历排期。

实验环境以 Unity **6000.3.22f1**、URP **17.3.0**、Amplify Impostors **1.0.2** 为起点，利用现有 PC/Mobile 渲染配置与插件示例逐步建立实验世界。这些版本是本次规划的环境记录，相关功能仍需按各阶段要求完成构建、运行与设备验证。

## 规划路线与取舍

1. **推荐：按技术问题推进，案例穿插。** 共用 Unity 实验世界，对流送、远景、可见性、光照等问题分别比较方案，每个里程碑验证双端。
2. **按游戏整套复刻。** 体验直观，但美术与玩法会挤占技术研究，且内部算法多未公开；只截取具有研究价值的局部场景。
3. **先建立通用框架或堆叠插件。** 易过早抽象，也可能跳过原理与测量；主线优先 Unity 现有能力和现有插件，遇到实测瓶颈后才扩展。

主要技术候选：GameObject / MonoBehaviour、URP、Additive Scene、Addressables、Mesh LOD、Amplify Impostors、Unity Terrain / Mesh 地形、AI Navigation、Unity 性能工具。Addressables 尚未安装，后续任务需验证版本再接入。HLOD、APV、GPU Resident Drawer 和 GPU 遮挡均为“需验证的候选”，不承诺全部采用。DOTS、自研 GPU 剔除、虚拟纹理等放入选做。

## 案例研究规则

- **A：原始公开资料确认。** 开发者演讲、官方技术文档、可核对的公开代码；记录日期和适用版本。
- **B：可重复观察。** 官方影像或自有实机观察，只证明可见行为与效果。
- **C：技术假设。** 根据画面或表现提出的实现解释，必须标明推测，并设计实验。
- 未取得讲稿全文时，官方简介只能证明公开讨论的议题，不能证明讲稿中的算法细节。历史博客不代表游戏当前完整架构。
- 每份研究卡包括：问题、来源、证据等级、方案、代价、替代方案、Unity 最小实验、PC/移动端差异、结论边界。
- 案例之间比较的是约束与方案；Unity 实验是借鉴实现，不能声称还原其他引擎内部。研究只使用可合法访问的资料与项目可用素材。

| 案例 | 优先研究问题 | Unity 实验方向 |
|---|---|---|
| 艾尔登法环 | 关卡数据、导航数据生成、资源依赖、内存诊断；地标和多层区域观察 | 分块元数据、导航烘焙、依赖可视化、地表/地下过渡 |
| Firewatch | 空间分组、路线与区域流送 | 距离网格、区域触发和混合调度的对照 |
| Rust | 动态世界、Impostor 提交、遮挡与环境音成本 | 密度压力测试、批次与剔除、分级模拟 |
| 地平线 | 资源管线、调度、内存、程序化局部布置 | 预算调度、依赖分组、确定性植被布置 |
| 旷野之息 | 探索空间、视线遮露、局部规则交互 | 灰盒路线、可控规则、卸载后的状态一致性 |

## 模块边界与共用约束

- **常驻层：** 玩家、相机、世界协调、配置、采样与状态服务。
- **世界数据：** 稳定 ChunkId、对象 ID、区域/层级、边界与资源地址；逻辑状态与场景实例分离。
- **流送层：** 计算目标驻留集合、调度和就绪；资源提供者负责加载句柄及释放，两者分离。
- **表现层：** 地形、植被、LOD/Impostor/HLOD、光照和环境；可见、不模拟、停用、卸载是不同操作。
- **模拟层：** 导航、交互、物理、动画与音效按预算分级，关键状态可跨卸载恢复。
- **工具层：** 分块编辑、派生数据生成、依赖/内存可视化、构建与回归。

PC 和移动端共用数据模型与正确性要求，分别设置视距、密度、图集、阴影、资源预算和模拟频率。任何优化都保留可比较的基线与回退路径。传统多场景遮挡数据不能按独立块自动合并；光照贴图、传统探针、APV、反射与遮挡需分别验证驻留边界，见文末官方来源。

## 任务组织与时间口径

共 **54 项主线任务、162 个行动步骤、8 项进阶选题**。可下载[结构化任务 JSON](/downloads/unity-open-world/roadmap.json)，用于导入个人任务工具或继续拆分。每个任务包含依赖、目的、步骤、产物和验收。建议单次投入约 2 小时，表中的次数只表示初始拆分尺度，不是工期承诺；遇到设备、资料或复杂实现问题时继续拆分，不通过缩减验收伪装完成。案例只需先明确当前技术问题，后续模块无需等待全部案例读完。

P0：当前基线任务；P1：依赖满足后推进的主线；进阶选题保留在候选池。阶段号用于分类，并非必须串行的排期；工具和性能工作随对应模块推进。

| 阶段 | 主题 | 任务数 | 阶段验收 |
|---|---|---:|---|
| 00 | 目标、工程基线与双平台测量 | 4 | 明确测试设备、预算和复现路线，PC 与移动端各有一份可追溯基线。 |
| 01 | 成熟作品案例与方案对比 | 6 | 案例结论有来源和证据等级，并映射到后续 Unity 实验。 |
| 02 | 统一实验世界与内容规范 | 4 | 同一灰盒世界能暴露开阔、遮挡、垂直和密集场景的不同瓶颈。 |
| 03 | LOD、Impostor 与远景替身 | 4 | 远景在双平台可用，视觉差异和 CPU/GPU/内存收益均有数据。 |
| 04 | 世界分块与加载调度 | 4 | 完成可重复穿越的分块闭环，边界折返、传送和失败恢复均可验证。 |
| 05 | Addressables 与内存生命周期 | 4 | 真实打包资源完成加载和回收，循环巡游后的内存趋势可解释。 |
| 06 | 地形、植被与 HLOD | 4 | 地形边界、植被密度和聚合远景在流送中正确交接。 |
| 07 | 可见性、批次与 GPU 渲染 | 4 | 按场景结构决定剔除方式，保留确有收益且视觉正确的方案。 |
| 08 | 光照、探针与环境连续性 | 4 | 分块加载后的静态与动态受光连续，各类烘焙数据的驻留边界明确。 |
| 09 | 导航、交互与分级模拟 | 4 | 世界卸载与重载不破坏可见区域的行为、交互和状态。 |

## 详细任务

### 阶段 00：目标、工程基线与双平台测量

阶段验收：明确测试设备、预算和复现路线，PC 与移动端各有一份可追溯基线。

#### 00.01 确定双平台设备与性能预算

优先级：P0；预计投入：2 次；依赖：无；状态：未开始。

目标：明确实验的共同约束，避免根据开发机表现选方案。

- [ ] 1. 记录 PC 与移动端设备、OS、图形 API、分辨率、可用测试条件；Android/iOS 分别标记实际覆盖情况。
- [ ] 2. 为每档设备填写目标帧率、CPU/GPU 帧耗时、内存上限、流送峰值和最大移动速度；先测量再确认数值。
- [ ] 3. 保存设备与预算表，标明尚未实测的平台和预算调整规则。

产物：设备矩阵、性能预算表。

验收：至少有一台 PC 和一台移动设备作为基线；不可用的平台明确标为未验证，不用 Editor 结果代替。

#### 00.02 记录工程与资源基线

优先级：P0；预计投入：1 次；依赖：00.01；状态：未开始。

目标：固定当前 Unity、URP 与插件环境。

- [ ] 1. 记录 Unity 6000.3.22f1、URP 17.3.0、Amplify Impostors 1.0.2，以及当前 PC/Mobile 画质配置。
- [ ] 2. 确认现有第三方资源的许可和备份方式，建立版本管理方案并排除 Library、Temp、obj 等生成目录。
- [ ] 3. 建立实验记录模板：问题、假设、配置、步骤、数据、结论、来源。

产物：环境清单、实验记录模板、版本管理规则。

验收：能从记录还原实验环境；自有实验与插件原文件的边界清楚。

#### 00.03 建立自动巡游与指标采样

优先级：P0；预计投入：3 次；依赖：00.02；状态：未开始。

目标：让技术方案在同一路线、同一场景密度下比较。

- [ ] 1. 设计固定种子和相机路线，覆盖平原、密林、建筑遮挡、洞口与高速移动。
- [ ] 2. 记录 CPU/GPU 时间、帧时间 P50/P95/P99、长帧次数、GC、批次、三角形、内存与加载事件。
- [ ] 3. 分别执行冷启动和预热后的三次采样，记录构建、图形设置和采样开销。

产物：巡游样例、采样结果、基线报告。

验收：相同配置可重复运行；GPU 指标若平台不可用需注明，不能填推测值。

#### 00.04 完成 PC 与移动端最小构建

优先级：P0；预计投入：2 次；依赖：00.03；状态：未开始。

目标：尽早暴露构建、输入、着色器和设备差异。

- [ ] 1. 使用现有 SampleScene/插件示例做最小 Player 构建，配置 PC 输入与移动端的最低可用控制。
- [ ] 2. 分别验证画面、移动、Impostor 材质和日志采集，保留设备截图与构建信息。
- [ ] 3. 对照 Editor、Development Player 与常规 Player 的结果，说明各自测量用途。

产物：双平台可运行样例与验证记录。

验收：PC 和至少一个移动设备能运行最小样例；所有后续里程碑继续保留双平台验证。

### 阶段 01：成熟作品案例与方案对比

阶段验收：案例结论有来源和证据等级，并映射到后续 Unity 实验。

#### 01.01 研究《艾尔登法环》的世界数据与诊断工具

优先级：P1；预计投入：3 次；依赖：00.02；状态：未开始。

目标：从大型内容组织和生产工具入手。

- [ ] 1. 阅读 CEDEC 2022 官方讲座简介，并获取可合法访问的讲稿或视频；未取得全文时注明仅依据简介。
- [ ] 2. 围绕关卡数据组织、导航数据自动生成、资源依赖可视化、内存超限调试整理问题与证据。
- [ ] 3. 结合实机或官方影像观察地标、地表/地下与区域过渡；观察与实现推断分开，提出 Unity 小实验。

产物：Elden Ring 研究卡与实验映射。

验收：形成一份来源标注的研究卡，至少映射到分块、导航或诊断工具中的两个任务；没有资料的内部实现保持未知。

#### 01.02 研究 Firewatch 的空间分组与流送

优先级：P1；预计投入：2 次；依赖：00.02；状态：未开始。

目标：比较路线与区域驱动的流送方式。

- [ ] 1. 阅读开发者 GDC《Making the World of Firewatch》资料，记录年代与实际讨论范围。
- [ ] 2. 整理空间分组、路线约束、触发区域和远景保留所解决的问题；不把流送证据等同于遮挡实现证据。
- [ ] 3. 设计同一灰盒路线的距离网格与区域触发两种加载实验。

产物：Firewatch 研究卡与流送对比方案。

验收：说明区域方案适合什么地形、在哪些自由移动场景下存在风险，并链接 Unity 对比实验。

#### 01.03 研究 Rust 的动态世界与渲染优化演进

优先级：P1；预计投入：3 次；依赖：00.02；状态：未开始。

目标：研究动态内容为何需要不同的可见性与批次策略。

- [ ] 1. 按发布年代阅读 Facepunch 的动态遮挡、Impostor 和性能日志。
- [ ] 2. 分别梳理距离剔除、动态遮挡、Impostor 批次和环境音调度；记录每次优化的前提与代价。
- [ ] 3. 提出高密度物件场景中的 CPU 提交、GPU 渲染、内存三组对比，不把历史博客当作当前完整架构。

产物：Rust 研究卡与实验假设。

验收：研究结论有时间边界；至少包含一次收益可能为负的案例分析。

#### 01.04 研究《地平线》的资源调度与程序化布置

优先级：P1；预计投入：3 次；依赖：00.02；状态：未开始。

目标：比较内容管线、运行时流送与 GPU 布置的职责。

- [ ] 1. 阅读 Guerrilla 官方 Streaming the World 与 GPU-Based Procedural Placement 的讲座简介及可访问材料。
- [ ] 2. 绘制资源生产、依赖、调度、内存、局部布置的流程图，并区分离线生成与运行时生成。
- [ ] 3. 提出 Unity 分块元数据、预算调度和确定性植被布置实验，列出移动端需降级的环节。

产物：Horizon 研究卡、数据流图。

验收：流程图中每个已确认结论可追溯；Unity 方案标为借鉴实现，不能声称复刻 Decima 内部。

#### 01.05 研究《旷野之息》的探索空间与系统交互

优先级：P1；预计投入：3 次；依赖：00.02；状态：未开始。

目标：把关卡组织和局部模拟需求纳入大世界技术规划。

- [ ] 1. 阅读 Nintendo 的 GDC 2017 官方演讲可访问内容，并用官方影像或自有实机片段建立观察记录。
- [ ] 2. 分析地形遮露、远处目标、路线选择与可交互物理规则；未有原始资料的算法不做定论。
- [ ] 3. 设计一个小范围探索路线与一种规则交互，例如火源/可燃物，讨论区域卸载后状态如何保存。

产物：Zelda 研究卡、探索与交互实验草图。

验收：产出空间示意与最小交互实验设计，避免扩张成完整动作 RPG 开发。

#### 01.06 建立跨作品技术决策矩阵

优先级：P1；预计投入：2 次；依赖：01.01、01.02、01.03、01.04、01.05；状态：未开始。

目标：按问题选择方案，而不是按作品照搬整套架构。

## 验收与证据规则

- 学习/调研完成：有原始来源、问题与证据等级，能提出可验证实验；不等同实现完成。
- 功能完成：对应样例在 Player 或规定环境验证了正常与异常路径，并保存产物。
- 性能结论：同设备、构建、场景、路线和配置对照，记录重复次数、帧时间与内存；不能只给 FPS 或三角形数量。
- 阶段验收：PC 与至少一个实际移动设备有记录；Android/iOS 未测的一侧明确写未验证。构建、Editor 预览、自动检查与真机视觉分别记载。
- 每个模块记录配置和局限；采用候选方案不是任务的必然结果，证据充分的“不采用”也是有效研究产物。
